# requirements-to-prd

**把原始需求整理成可评审、可追溯的 PRD。**

一个采用 [Agent Skills](https://agentskills.io/specification) 格式的需求分析与 PRD 编写技能，面向支持该格式的 AI 助手。支持从招标文件、需求书、功能清单和访谈记录出发，梳理产品范围、用户任务、业务流程和页面字段，保留原文依据，并指出仍需决定的问题。

当前版本：**v1.7** · [MIT License](LICENSE) · [技能定义](SKILL.md) · [安装](#安装) · [公开样本与评测](evals/README.md) · [变更记录](CHANGELOG.md)

## 为什么做这个项目

原始材料往往同时包含功能描述、技术要求、实施约束和未解决的业务问题。直接扩写成一份长文档，容易遗漏要求，也容易把推测写成已经确定的规则。

requirements-to-prd 为 AI 提供一套需求整理与核验方法，让生成的文档能够回答：

- 这个产品服务谁，要完成哪些任务？
- 每项设计对应哪条原始要求？
- 业务如何流转，页面需要展示和填写什么？
- 哪些内容已有依据，哪些只是候选方案？
- 当前可以继续做什么，哪些分支还缺少决定或验证？

## 主要能力

| 能力 | 说明 |
|---|---|
| 需求追溯 | 保留材料版本、条款或段落引用，已有需求 ID 在修订中保持可追踪 |
| 业务梳理 | 按用户任务、业务对象、角色和操作结果组织设计，覆盖自动处理和非页面要求 |
| 候选方案 | 信息不全时给出有依据、带假设的候选路径，分别标明事实、建议和待确认项 |
| 页面字段细则 | v1.7 默认展开范围内页面的查询、列表、详情、表单和操作输入，以及类型、必填、默认值、权限和校验 |
| PRD 评审 | 通过具体输入和业务场景检查流程、字段、状态与权限，说明后续设计和开发的条件 |
| 局部修订 | 按反馈调整相关页面、动作和上下游关系，保留其他已确认内容 |

## 适用场景

- 将招标文件或需求书转成产品需求文档，并逐项核对覆盖情况。
- 把零散功能清单、访谈记录整理成可讨论的业务方案。
- 在进入原型和开发前，补充页面字段、操作条件和未决事项。
- 评审已有 PRD，检查遗漏、矛盾和需要研发自行猜测的内容。
- 对既有设计进行局部调整，检查变更影响。

输入材料需要由当前 AI 环境实际读取。DOCX、PDF 等文件的解析能力取决于宿主环境，本仓库本身不包含文件解析器。

## 平台兼容与验证

核心内容由 `SKILL.md` 和 Markdown 参考文档组成，不依赖 Codex 专用 API。支持 Agent Skills 格式的工具可以按各自方式加载；安装目录、技能触发、参考文件读取和输入材料解析能力仍由宿主工具提供。

| 工具 | 格式与使用说明 | 本仓库验证情况 |
|---|---|---|
| Codex | 本仓库提供安装示例，使用全局技能目录 | 已安装并用于 PRD 生成与评审 |
| Claude Code | 支持 Agent Skills，可读取技能及配套参考文件；见[官方文档](https://code.claude.com/docs/en/skills) | 已记录 CLI 全量规则注入对照；原生技能加载尚未验证 |
| Cursor | 支持技能目录和 `SKILL.md`；见[官方文档](https://cursor.com/help/customization/skills) | 尚未实测本技能 |

格式支持不代表各平台的生成效果已经验证，也不保证不同模型输出相同。迁移后可使用 [回归场景](evals/scenarios.md) 检查技能加载、来源追溯、字段细则和业务推演；实际生成的 PRD 仍需评审。

## 安装

### 在 Codex 中安装

向 Codex 发送：

```text
请使用 skill-installer，从 https://github.com/xtianyaa/requirements-to-prd
安装 requirements-to-prd 到全局技能目录。
使用发布标签 v1.7。
如果已经安装，请备份旧版后更新。
```

使用[发布标签 v1.7](https://github.com/xtianyaa/requirements-to-prd/releases/tag/v1.7)固定安装快照；Release、技能元数据与变更记录对应同一版本。安装后在下一轮对话中调用。

### 手动安装到 Codex、Claude Code 或 Cursor

1. 下载对应 Release，或克隆本仓库并执行 `git checkout v1.7`。
2. 在所用工具的技能目录下创建 `requirements-to-prd` 文件夹，个人技能目录见下表。
3. 将 `SKILL.md`、`LICENSE`、`README.md`、`references/` 复制进去；`evals/`、`scripts/` 和 `CHANGELOG.md` 按验证或查阅需要保留，无需复制 `.git/`。
4. 按对应工具的技能加载方式启用，并使用下方提示词。本仓库尚未验证 Claude Code、Cursor 的原生技能加载，请先确认技能和参考文件能够被读取。

默认个人技能目录为：

| 工具 | 目录 |
|---|---|
| Codex | `~/.codex/skills/requirements-to-prd/` |
| Claude Code | `~/.claude/skills/requirements-to-prd/` |
| Cursor | `~/.cursor/skills/requirements-to-prd/` |

`~` 表示用户主目录，Windows 下可用 `%USERPROFILE%` 定位，例如 Codex 的目录为 `%USERPROFILE%\.codex\skills\requirements-to-prd`。Codex 设置了 `CODEX_HOME` 时，使用其下的 `skills/requirements-to-prd`；项目级安装或受管理环境按对应工具的文档配置。更新前请备份已有目录。

## 快速开始

附上原始文件，或提供 AI 可访问的文件路径，然后说明期望的输出范围。以下提示词可直接使用。

### 从需求书生成 PRD

```text
使用 requirements-to-prd，将这份需求书整理成完整 PRD。
保留原文来源和需求 ID，包含业务流程、页面字段细则与验收场景。
原文没有确定的规则请标明，并给出有依据的候选方案。
输出独立的 Markdown 文件。
```

### 评审已有 PRD

```text
使用 requirements-to-prd，评审这份 PRD 是否可以进入功能设计和开发。
按优先级列出具体问题、文档位置、影响和最小补充内容。
区分设计遗漏、业务尚未决定和下一阶段的技术规格。
本轮只生成评审报告，不修改原 PRD。
```

### 局部修改

```text
使用 requirements-to-prd，将审批操作并入现有详情页，保留审批待办入口。
检查相关字段、权限、状态、入口和返回方式，并核对原需求是否仍然覆盖。
只修改受影响的内容。
```

只需要概要时，明确说明“本轮仅梳理范围与业务概要，不展开页面字段”。已有文档模板时，可同时提供模板并要求沿用。

## 会得到什么

默认交付独立的 Markdown 功能设计；明确要求 PRD 时组织为 PRD，也可沿用指定模板。内容通常包括：

- 产品目标、范围、材料依据和需求对应关系。
- 用户角色、业务对象、主要流程与关键操作。
- 页面内容、字段、校验、读写条件和失败反馈。
- 自动处理、指标、非功能与实施要求中适用的部分。
- 候选方案、待决定事项、场景推演和后续工作条件。

页面字段的表达示意如下，实际字段和规则依据项目材料生成：

| 页面 / 动作 | 字段 | 类型 | 条件与校验 |
|---|---|---|---|
| 事件详情 / 申请延期 | 延期原因 | 多行文本 | 申请时必填，保留原输入 |
| 事件详情 / 申请延期 | 拟延期至时间 | 日期时间 | 与原期限比较；申请不直接改变有效期限 |
| 事件详情 / 查看进度 | 当前状态 | 只读结果 | 由已定义的业务动作产生 |

具体章节和表格按项目复杂度组织，不要求每份材料套用同一套目录。字段表和场景推演仍需评审，示例不代表项目业务已确认。

## 公开样本与评测

仓库提供三个合成需求及逐项评分标准：公告浏览、项目台账、企业联系人。材料不包含客户资料；实际输出是一次生成样本，不是唯一正确的 PRD 模板。

输入、对照协议、运行记录和工具说明见[评测目录](evals/README.md)。核心技能是 Markdown，无 Python 依赖；请求准备与记录完整性检查工具需要 Python 3.10+，不调用模型、不自动判断业务正确性。

评测区分不使用技能的 baseline 与使用 v1.7 的 skill 组，保留结果和失败记录。单模型、小样本、单次运行不能证明普遍提升；工具安装或格式兼容也不等于实际生成质量已经验证。

首轮 [v1.7 对照记录](evals/runs/2026-10-20-v1.7/README.md)包含3组输入、6份原始输出、逐项AI审阅和失败记录。返回的模型 ID 为 `deepseek-v4-pro`，不作为 Claude Sonnet 或跨模型验证。发现的问题保留在报告中。

## 能力边界

这个 Skill 提供需求分析和文档生成方法，输出质量仍取决于材料完整性、模型执行和人工评审。

- 缺少依据的法规阈值、评分公式、审批岗位或授权规则，会作为待决定内容保留。
- 页面字段细则不包含完整视觉原型、数据库物理结构或接口请求响应规格。
- 文档推演、原型验证和真实系统测试分别记录；需求覆盖或字段齐全不能直接证明可开发、已实现或验收通过。
- 外部数据、模型、解密设备等能力，需要真实授权、样本和验证证据。

## 仓库结构

```text
requirements-to-prd/
├── SKILL.md                              # 技能入口与核心规则
├── README.md                             # 项目介绍与使用指南
├── LICENSE                               # MIT License
├── CHANGELOG.md                          # 发布与变更记录
├── references/
│   ├── page-composition-rules.md          # 页面组合、导航和多视图
│   ├── page-data-flow.md                  # 页面读写、关联与历史结果
│   ├── page-field-specification.md        # 页面字段细则
│   └── business-readiness.md              # 业务推演与后续工作条件
├── evals/
│   ├── README.md                          # 对照协议与复现说明
│   ├── scenarios.md                       # 文字回归场景
│   ├── cases/                             # 合成输入与逐项 rubric
│   └── runs/                              # 实际输出、记录和评审
└── scripts/
    └── eval_bundle.py                     # 准备请求、核验记录完整性
```

辅助工具的完整性测试见 `tests/`，可运行 `python -m unittest discover -s tests`；不调用模型，也不验证业务生成效果。
