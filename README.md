# requirements-to-prd

版本 1.5。将招标文件、需求书、功能清单或访谈整理为可评审的功能设计或 PRD，保留来源、业务分歧和局部修订关系。

## 使用方式

提供原始材料并说明本轮范围：

> 使用 requirements-to-prd，将这份原始需求整理成可评审的 PRD。说明业务和页面如何支持主要任务，保留来源与关键问题；未知流程给出带假设的待评审方案。

局部修订可直接指定任务：

> 将审批操作并入现有详情页，保留审批待办入口，检查权限、返回方式和原需求是否仍然覆盖。

## 交付方式

默认输出独立的 Markdown 功能设计；用户要求 PRD 或指定模板时直接沿用。章节、图表、台账与矩阵按任务复杂度选择，不为固定格式扩充业务。只有涉及复杂页面划分或数据关系时，才读取对应参考文件。

设计描述完整、业务已确认、系统已实现和验收通过分别判断。数据库、API 和架构设计不默认追加。

## 文件

- [SKILL.md](SKILL.md)：范围、依据、需求粒度、不确定性、交付与核验。
- [页面组合规则](references/page-composition-rules.md)：有实质取舍的拆合页、导航和多视图设计。
- [页面数据与操作规则](references/page-data-flow.md)：复杂读写、跨页面关联和历史结果。

## v1.5 调整

合并重复约束，移除固定表格和专项算例，将详细规则改为有条件读取。保留候选主路径、问题按影响分级、完整任务粒度、覆盖与确认分离，以及自动处理和非功能要求的独立承载。目标是减少过程限制；实际生成质量仍需对照测试验证。
