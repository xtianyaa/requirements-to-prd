# requirements-to-prd

版本 1.7。将招标文件、需求书、功能清单或访谈整理为可评审的功能设计或 PRD，默认包含范围内页面字段细则，保留来源、业务分歧和局部修订关系，并说明后续设计与开发的可开展范围。

## 使用方式

提供原始材料并说明本轮范围：

> 使用 requirements-to-prd，将这份原始需求整理成可评审的 PRD。说明业务和页面如何支持主要任务，保留来源与关键问题；未知流程给出带假设的待评审方案。

包含页面时，默认逐页说明查询、列表、详情、表单和相关操作输入的字段、控件/类型、来源、必填/默认、读写条件、校验及失败反馈。只要概要时可明确说“本轮仅做范围与业务概要，不展开字段细则”。

局部修订可直接指定任务：

> 将审批操作并入现有详情页，保留审批待办入口，检查权限、返回方式和原需求是否仍然覆盖。

## 交付方式

默认输出独立的 Markdown 功能设计；用户要求 PRD 或指定模板时直接沿用。章节、图表、台账与矩阵按任务复杂度选择，不为固定格式扩充业务。涉及复杂页面、数据关系或业务推演时，按需读取对应参考文件。

设计描述完整、业务已确认、可进入何种后续工作、系统已实现和验收通过分别判断。评审 PRD 不自动升级为开发规格；数据库、API 和架构设计不默认追加。交付时说明哪些内容可先行，哪些决定或证据仍影响后续工作。

## 文件

- [SKILL.md](SKILL.md)：范围、依据、需求粒度、不确定性、交付与核验。
- [页面组合规则](references/page-composition-rules.md)：有实质取舍的拆合页、导航和多视图设计。
- [页面数据与操作规则](references/page-data-flow.md)：复杂读写、跨页面关联和历史结果。
- [页面字段细则](references/page-field-specification.md)：逐页字段、控件、值域、来源、条件必填、状态差异及校验推演。
- [业务推演与就绪判断](references/business-readiness.md)：规则、状态、权限、跨系统失败及能力依赖的适用检查。
- [回归场景](evals/scenarios.md)：用于修改 skill 后检验实际输出，不是生成每份 PRD 时的固定模板。

## v1.7 调整

在 v1.6 的业务推演和按模块就绪判断基础上，将页面字段细则纳入默认交付范围；用户明确要概要时可缩减。补充逐页字段和跨查询/展示/表单/状态的一致性核验，未知属性局部标明，不把整页字段推迟给下一阶段，也不冒充业务确认。字段细则不代表已提供完整视觉原型、数据库或API规格。
