# 企业项目台账 PRD

## 1. 文档说明

- 本文档为「企业项目台账」的独立中文产品需求文档（PRD），供需求评审使用。
- 本材料完全虚构，用于公开评测，不包含任何客户资料。
- 本文档仅描述业务规则与交互行为，**不设计数据库表结构与 API 接口**。
- 需求编号沿用原始需求中的 `P01` ～ `P06`，便于追溯。
- 原文未明确给出的规则，一律以「【候选】」或「【待决定】」标注，不作为已确认结论。
- 文中「必填」若无特别说明，均指**提交动作时的校验必填**；「暂存」动作仅要求名称，详见 5.5。

## 2. 术语与角色

| 术语 | 说明 |
| --- | --- |
| 企业 | 项目归属单位。项目台账按企业隔离。 |
| 企业项目管理员 | 唯一可操作本功能的角色，只能维护**本企业**的项目。 |
| 项目 | 台账的核心对象，包含名称、类型、预算、起止日期、服务商、状态等字段。 |
| 服务商 | 本企业服务商目录中的供应商条目，仅「外包」类型项目需要选择。 |
| 服务商目录 | 本企业已有且维护的服务商集合，是外包项目选择服务商的唯一数据来源。 |
| 状态 | 由「暂存 / 提交」动作产生的项目状态，取值见 6。 |

## 4. 业务规则汇总

### 4.1 数据范围与权限（P01、P06）
- 企业项目管理员仅能查询、查看、编辑**本企业**的项目。
- 服务商选择也仅限**本企业已有服务商目录**。
- 列表与查询均默认并强制限定在当前管理员所属企业范围内，不支持跨企业查看。
- 本功能**不含审批流程**，**不含导出功能**。

### 4.2 必填规则（P05）
- **暂存**：仅「项目名称」必填。
- **提交**：以下字段必填——
  - 项目名称
  - 类型
  - 预算
  - 开始日期
  - 结束日期
  - 服务商：**仅当类型 = 外包时必填**；类型 = 内部时不要求。

### 4.3 类型与服务商（P02）
- 类型为枚举，仅两个取值：**内部**、**外包**。
- 类型 = 外包：必须从**本企业已有服务商目录**中选择一个服务商。
- 类型 = 内部：不要求服务商，服务商字段允许为空。
- 【待决定】类型在「外包 → 内部」或「内部 → 外包」切换后，已填写的旧服务商如何处理，原文未规定。候选方案见 8。

### 4.4 预算（P03）
- 单位：**万元**。
- 精度：最多 **两位小数**。
- 取值：**不小于 0**（即 ≥ 0，允许为 0）。
- **缺失 ≠ 0**：字段留空时按「未填写」处理，不得当作 0；留空在提交时视为必填缺失而校验失败。

### 4.5 起止日期（P04）
- 结束日期 **不得早于** 开始日期（允许等于，即同一天为合法）。
- 日期输入**不强制默认当天**：开始日期、结束日期均不自动回填当前日期，允许留空（草稿态）或由用户显式选择。

### 4.6 状态（P06）
- 状态**由动作产生**，不由用户直接编辑。
- 取值见 6（状态机）。

## 5. 功能细则

### 5.1 查询 / 列表（P01、P06）

**筛选条件**

| 筛选项 | 说明 |
| --- | --- |
| 名称 | 按项目名称筛选；【候选】建议支持模糊匹配（包含匹配）。 |
| 类型 | 按「内部 / 外包」筛选；可多选或全部。 |
| 状态 | 按状态筛选，取值与状态机一致（见 6）。 |

- 各筛选条件可组合使用；均为可选项，不选择时返回全部本企业项目。
- 筛选范围始终限定为本企业（见 4.1）。

**列表展示字段**

| 字段 | 说明 |
| --- | --- |
| 名称 | 项目名称 |
| 类型 | 内部 / 外包 |
| 预算 | 万元，最多两位小数 |
| 起止日期 | 开始日期、结束日期 |
| 状态 | 草稿 / 已提交 |

- 【候选】列表默认排序建议按「最近更新」倒序；原文未规定，可评审后确认。

### 5.2 详情（P01、P06）

详情在列表字段基础上**额外显示服务商**：

| 字段 | 说明 |
| --- | --- |
| 名称 | 项目名称 |
| 类型 | 内部 / 外包 |
| 预算 | 万元，最多两位小数 |
| 开始日期 | — |
| 结束日期 | — |
| 服务商 | 仅类型 = 外包时有值；内部项目为空 |
| 状态 | 草稿 / 已提交 |

- 【待决定】详情是否展示创建时间、更新时间、操作人等系统字段，原文未规定。

### 5.3 新增（P01）

- 进入空白的项目编辑界面，字段均为空。
- 【候选】新增动作即创建一条空白草稿记录；另一种理解是仅打开空白表单、保存时才落库。二者对用户可见行为一致，具体落库时机留待评审决定。
- 新增不触发提交校验，允许以空表单或部分字段进行暂存。

### 5.4 草稿编辑（P01）

- 仅**草稿状态**（未提交）的项目可编辑。
- 可编辑字段：名称、类型、预算、开始日期、结束日期、服务商。
- 状态字段只读，由动作产生，不可手工修改。
- 已提交项目的业务编辑字段只读（见 4.6 / 5.6）。

### 5.5 暂存（P01、P05）

- 校验规则：仅「项目名称」必填；其余字段均可为空。
- 暂存后项目进入**草稿**状态，可在列表中被检索到。
- 暂存**不校验**类型、预算、起止日期、服务商的完整性。
- 预算留空时保持「未填写」，不写入 0（见 4.4）。

### 5.6 提交（P01、P05）

提交时按以下顺序校验，任一不满足则失败并给出对应提示：

1. **名称必填**：缺失则失败。
2. **类型必填**：必须为「内部」或「外包」。
3. **预算必填**：必须填写且 ≥ 0、最多两位小数。
4. **开始日期必填**。
5. **结束日期必填**。
6. **结束日期 ≥ 开始日期**：否则失败。
7. **服务商条件必填**：类型 = 外包时必填，且必须来自本企业服务商目录；类型 = 内部时不要求。
8. 预算格式校验：最多两位小数、≥ 0。

- 提交成功后项目进入**已提交**状态。
- 提交后，**全部业务编辑字段只读**，不可再编辑或暂存（是否支持撤回见 8【待决定】）。
- 本功能无审批环节：提交即终态，不进入任何审批流。

## 9. 具体输入推演

### 9.1 合法操作推演

**场景 A：内部项目的完整流程**
1. 管理员进入「新增」，填入名称「内部研发项目 A」、类型「内部」、预算 `12.50`、开始日期 `2026-01-01`、结束日期 `2026-06-30`，服务商留空。
2. 点击「暂存」：名称已填，校验通过，进入草稿状态。
3. 点击「提交」：名称、类型、预算、起止日期均满足；类型 = 内部，服务商不要求 → 提交成功，进入已提交状态，字段只读。
- 结果：合法，服务商为空符合内部项目规则。

**场景 B：外包项目的完整流程**
1. 新增项目，名称「外包项目 B」、类型「外包」、预算 `0`、开始 `2026-03-01`、结束 `2026-03-01`，从本企业服务商目录选择「供应商 X」。
2. 暂存：名称已填，通过。
3. 提交：预算 0 ≥ 0 合法；结束 = 开始（同一天）合法；类型 = 外包且已选服务商 → 提交成功。
- 结果：合法，覆盖「预算允许为 0」与「结束可等于开始」两条边界。

**场景 C：暂存的最小合法输入**
- 仅填写名称「草稿 C」，其余全空，点击「暂存」→ 通过，进入草稿状态，预算为空（不当作 0）。
- 结果：合法，覆盖「暂存只要求名称」与「缺失≠0」。

### 9.2 关键失败推演

**失败 1：提交时预算留空**
- 输入：名称「X」、类型「内部」、预算留空、日期齐全。
- 提交 → 失败，提示「预算必填」。留空不会被当作 0 通过（P03、P05）。

**失败 2：预算为负或小数位超限**
- 预算 `-1` → 失败，提示「预算不小于 0」。
- 预算 `12.345`（三位小数）→ 失败，提示「最多两位小数」。

**失败 3：结束日期早于开始日期**
- 开始 `2026-06-30`、结束 `2026-06-29` → 提交失败，提示「结束日期不得早于开始日期」。

**失败 4：外包项目未选服务商**
- 类型「外包」、服务商留空、其余齐全 → 提交失败，提示「外包项目必须选择服务商」。

**失败 5：内部项目误带服务商的处理**
- 类型「内部」且已选某服务商：提交**不因服务商而失败**（内部不要求服务商）。是否清空展示取决于 Q1 决定。

**失败 6：暂存时名称留空**
- 名称留空点击「暂存」→ 失败，提示「项目名称必填」（即使其余字段已填）。

**失败 7：提交时缺少类型或日期**
- 类型未选 → 提交失败；开始或结束日期任一留空 → 提交失败（P05）。

**失败 8：跨企业访问**
- 管理员只能看到并维护本企业项目；访问他企业项目被数据范围拦截（P01）。
