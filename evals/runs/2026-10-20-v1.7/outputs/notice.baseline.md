# 公告浏览 PRD

> 本材料完全虚构，用于公开评测，不包含客户资料。

## 1. 概述与范围

面向访客提供已发布公告的查询与浏览能力。本轮仅覆盖访客侧查询与浏览，不包含后台维护、登录、审批、导出等能力。

| 需求编号 | 需求描述 | 本轮是否包含 |
| --- | --- | --- |
| N01 | 访客可以查看已发布公告，按标题关键词查询 | 是 |
| N02 | 打开详情后显示标题、正文、发布日期；可以返回列表 | 是 |
| N03 | 本轮只涉及访客查询与浏览，不包含后台维护、登录、审批、导出 | 是（范围约束） |

## 2. 页面与字段

### 2.1 公告列表页

- 查询条件：标题关键词（文本框）。
- 查询按钮：触发按标题关键词的查询。
- 列表字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 公告标题，点击进入详情 |
| 发布日期 | 公告发布日期 |

- 列表为空时显示空态提示（如“暂无符合条件的公告”）。

### 2.2 公告详情页

| 字段 | 说明 |
| --- | --- |
| 标题 | 公告标题 |
| 正文 | 公告正文内容 |
| 发布日期 | 公告发布日期 |

- 提供“返回”操作，返回列表页并保留原查询条件与列表位置（建议项，见第 4 节）。

## 3. 校验与场景说明

1. **关键词查询（N01）**：按标题做包含匹配（模糊查询），输入为空时返回全部已发布公告。
2. **仅展示已发布公告（N01）**：列表与详情仅展示状态为“已发布”的公告；未发布、已下架的公告不可见。
3. **详情展示（N02）**：详情页必须完整展示标题、正文、发布日期三个字段。
4. **返回列表（N02）**：从详情页返回后，应回到原列表页。
5. **异常与边界**：
   - 公告无标题或正文为空时，详情页仍需可打开并给出占位提示（如正文为空时显示“暂无正文”）。
   - 访问不存在或不可见的公告详情时，给出友好提示并引导返回列表（建议项）。
6. **范围约束（N03）**：本轮不提供公告的新增、编辑、删除、上下架、审批、登录鉴权、导出等功能入口。

## 4. 交互建议（原文之外，可评审后取舍）

以下为原文未明确、建议补充的交互，均已标注“（建议）”，不影响 N01–N03 的基线实现：

- **（建议）分页**：列表页在公告较多时提供分页，避免一次加载全部数据。
- **（建议）查询条件保留**：从详情返回列表时保留关键词与页码，提升浏览连续性。
- **（建议）发布日期排序**：列表默认按发布日期倒序展示最新公告在前。
- **（建议）正文格式化**：正文支持基本换行展示，保证可读性。
